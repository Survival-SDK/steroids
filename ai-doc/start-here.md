# Документация для AI-агентов проекта Steroids

Это главный файл документации для агентов Cursor.

## Поведенческие правила

Поведенческие правила агента находятся в `.cursor/rules/`

## Структура документации

### Контекст проекта

- **`ai-doc/project-structure.md`** — структура директорий проекта, организация модулей
- **`ai-doc/branch.md`** — описание изменений в текущей git-ветке, legacy vs new паттерны
- **`ai-doc/current.md`** — текущая задача, над которой ведется работа

### Технические гайды

- **`ai-doc/coding-style.md`** — кодстайл, правила именования, различия понятий (модуль vs контекст)
- **`ai-doc/oop-system.md`** — OOP-система движка (st_object_t, st_modctx_t, наследование)
- **`ai-doc/module-system.md`** — система модулей, регистрация, зависимости, инициализация
- **`ai-doc/luajit-bindings.md`** — создание LuaJIT FFI биндингов для модулей
- **`ai-doc/cmake-patterns.md`** — паттерны CMake для сборки модулей

## Порядок изучения (для новых агентов)

Рекомендуемый порядок изучения документации:

1. `start-here.md` (этот файл) — общий обзор
2. `project-structure.md` — понять структуру проекта
3. `coding-style.md` — базовые правила кода
4. `oop-system.md` — понять архитектуру
5. `module-system.md` — понять, как работают модули
6. `branch.md` — понять цель текущих изменений
7. `current.md` — понять текущую задачу
8. `luajit-bindings.md` и `cmake-patterns.md` — по необходимости

## Важные примечания

### О файлах branch.md и current.md

**Если `ai-doc/branch.md` или `ai-doc/current.md` не содержат текста** (пустые), это означает, что пользователь забыл их заполнить. **Напомни ему об этом.**

**Исключение:** `ai-doc/current.md` может быть пустым в середине диалога — это нормально, если содержимое устарело, но контекст задачи понятен из текущего диалога.

### Быстрый старт для типичных задач

- **Работа с кодом проекта:** изучи `branch.md`, `module-system.md` и `cmake-patterns.md`
- **Создание LuaJIT биндинга:** изучи `luajit-bindings.md`
- **Работа с OOP:** изучи `oop-system.md`
