# Кодстайл

## Язык и базовые правила
- **Язык и стандарт:** Определяется в `CMakeLists.txt` конкретного модуля. В основном используется C11.
- **Именование типов:** `st_xxx_t`
- **Именование функций модулей:** `st_<module>_<action>()` — обязательно для функций, заносимых  в таблицу функций (при этом сами поля в таблице не должны содержать этот префикс). Для внутренних функций, не заносимых в таблицу, префикс `st_` опционален (допустимо без префикса).
- **Именование контекстов модулей:** `st_<module>ctx_t`
- **Компиляция:** Используем `-fms-extensions` для поддержки безымянных структур (наследование)

## Структуры

### Именованная структура
```c
typedef struct st_xxx {
    ...
} st_xxx_t;
```

### Неименованная структура
```c
typedef struct {
    ...
} st_xxx_t;
```

### Наследование через безымянные структуры
```c
typedef struct {
    st_parent_t;  // Безымянное наследование от родителя
    int my_field;
} st_child_t;
```

## Вызов функций

### Через макросы (для объектов из других модулей)
Для всех контекстов и объектов, реализация которых находится в других C-файлах, используем макросы:

```c
// Для контекстов модулей
#define ST_XXXCTX_CALL(ctx, func, ...) \
    ((st_xxxctx_funcs_t *)((const st_object_t *)ctx)->funcs)->func(ctx, \
     ## __VA_ARGS__)

// Для объектов
#define ST_XXX_CALL(object, func, ...) \
    ((st_xxx_funcs_t *)((const st_object_t *)object)->funcs)->func(object, \
     ## __VA_ARGS__)
```

### Прямые вызовы (допустимо для локальных функций)
Допустимо использовать прямые вызовы функций для классов, реализация которых находится в текущем C-файле (по имени функции, не через таблицу функций). Например, в C-файле с реализацией контекста логгера можно напрямую вызывать функции логгера, а также функции `st_object_t` и `st_modctx_t` для контекста логгера.

Это не строгое правило — можешь использовать макросы везде для единообразия.

## Перенос длинных строк

### Общие правила

1. **Длину строки желательно ограничивать 80 символами** (не строго, но очень желательно)
2. **При переносе добавляем один пробел к отступу** - это отличает перенос от вложенного блока кода
3. **Применяется к C, Lua и CMake**
4. **Не исправляй и не сообщай** о неправильных отступах в существующем коде - правила только для нового кода

### Конкретные кейсы

#### Определение функционального типа (typedef)

```c
typedef void (*st_matrix3x3_clone_t)(const st_matrix3x3ctx_t *matrix3x3_ctx,
 st_matrix3x3_t *dst, const st_matrix3x3_t *matrix);
```

Открывающая скобка на первой строке, продолжение с **+1 пробелом** отступа.

#### Вызов функции или макроса

```c
return ST_MODSMGR_CALL(plugin_ctx->modsmgr, load_module, modinit_func,
 force);
```

Аргументы, не поместившиеся на первую строку, переносятся с **+1 пробелом** отступа.

#### Вызов внутри условия или выражения

```c
if (!st_utl_strings_equal(ST_MODDATA_CALL(found_modules[i], get_name),
 "simple"))
```

Продолжение размещается с **+1 пробелом** отступа.

#### Разрыв строкового литерала

```c
fprintf(stderr, "steroids: Missing module of subsystem \"%s\" as "
 "prerequisite of module \"%s_%s\"\n",
 prereqs[i].subsystem, ST_MODDATA_CALL(module_data, get_subsystem),
 ST_MODDATA_CALL(module_data, get_name));
```

- Строковый литерал разрывается на части (C автоматически склеит)
- Вторая часть с **+1 пробелом** отступа
- Остальные аргументы: сначала пытаемся разместить на строке с остатком литерала
- Если не помещаются - на новой строке с **+1 пробелом** отступа

#### Аргументы с новой строки

```c
typedef void (*st_matrix3x3_translation_t)(
 const st_matrix3x3ctx_t *matrix3x3_ctx, st_matrix3x3_t *matrix, float x,
 float y);
```

Если даже первый аргумент не помещается:
- Открывающая скобка остается на первой строке
- Все аргументы начинаются с новой строки с **+1 пробелом**
- Если аргументы снова не помещаются - применяем стандартное правило (+1 пробел)

#### Вложенные вызовы

```c
ST_OUTER_CALL(arg1, 
 ST_INNER_CALL(inner_arg1, inner_arg2, inner_arg3), 
 arg3);
```

Внутренний вызов рассматриваем как неделимый аргумент. Если внутренний вызов не помещается на одну строку - действуй на свое усмотрение.

#### Условные выражения с логическими операторами

```c
if (condition1 && condition2 && condition3 && very_long_condition4
 && condition5)
```

Стараемся переносить логический оператор на новую строку с **+1 пробелом** отступа.

### Исключения

#### 1. Каждый аргумент на новой строке (не из-за лимита 80 символов)

```c
some_function(
    arg1,
    arg2,
    arg3
);
```

Используем отступ **4 пробела** для каждого аргумента.

#### 2. Тернарный оператор

```c
return zip
    ? st_plugin_load_impl(plugin_ctx, zip, "", force)
    : false;
```

Используем отступ **4 пробела** для веток тернарного оператора.

#### 3. Инициализаторы массивов и структур

```c
static const st_modprerq_t mod_prereqs[] = {
    {"logger", NULL},
    {"subsystem", "name"},
    {0}
};
```

Используем отступ **4 пробела** внутри фигурных скобок.

### Сложные кейсы (на усмотрение AI)

Следующие ситуации слишком сложны для строгих правил - действуй на свое усмотрение:

- Структурные инициализаторы (compound literals) внутри вызовов функций
- Очень длинные приведения типов (cast) в вызовах функций
- Цепочки вызовов методов (если встречаются в Lua)
- Множественные уровни вложенности вызовов

В таких случаях приоритет: читаемость > строгое следование правилам.
